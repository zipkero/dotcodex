# Go 작업 기준

## 적용 범위
- Go 파일을 수정하거나 검토할 때 적용한다.

## 코드 작성
- `gofmt` 또는 `go fmt` 결과를 기준으로 삼는다.
- 기존 프로젝트가 달리 정하지 않으면 표준 라이브러리와 작은 명시적 구현을 우선한다.
- 패키지 경계는 역할 중심으로 유지한다.
- 새 추상화는 독립된 책임이나 재사용 경계가 확인될 때 도입한다.

## 오류와 동시성
- 오류는 숨기지 말고 호출자가 판단할 수 있는 맥락 정보와 함께 반환한다.
- `panic`은 초기화 실패나 복구 불가능한 프로그래밍 오류에만 제한한다.
- goroutine을 추가하거나 수정할 때는 종료 조건, 취소, 채널 종료 책임을 확인한다.
- `context.Context`가 이미 흐르는 경로에서는 취소와 시간 제한 전달을 끊지 않는다.

## 테스트
- 기존 테스트 관례를 따른다.
- 순수 로직은 table-driven test를 우선 고려한다.
- 프로젝트 관례가 없고 Go 코드 동작을 바꿨다면 `go test ./...`를 우선 검증 명령으로 고려한다.

## 주석
- `Go doc`은 프로젝트 관례와 linter 설정을 따른다.
