# 언어별 작업 기준

## 적용 범위
- 이 문서는 전역 언어별 기준의 진입점이다.
- 프로젝트의 `AGENTS.md`, formatter, linter, compiler, test 설정이 있으면 그 기준을 우선한다.
- 여러 언어가 함께 바뀌면 각 언어 기준을 해당 파일에만 적용하고, 공통 변경 판단은 현재 프로젝트 관례를 우선한다.

## 공통 기준
- 공개 API, exported type, 컴포넌트 props, 직렬화 형태를 바꾸면 호출부·테스트·문서 영향을 함께 확인한다.
- 오류, null, 비동기, 취소, 자원 소유권처럼 빠뜨리면 결함으로 이어지는 경계를 우선 확인한다.
- 리뷰 의견은 수정 가능한 구체 지점에 연결하고, 선호 차이만 있는 의견은 실제 유지보수 위험이 있을 때만 남긴다.

## 주석
- 주석은 코드만으로 드러나지 않는 정보가 있을 때만 간결하게 쓴다.
- 한 줄을 우선하되, 여러 조건이나 제약을 설명해야 하면 읽기 쉬운 의미 단위로 나눈다.
- 선언 위에는 이름과 시그니처만으로 드러나지 않는 역할이나 계약을 적고,
  코드 안에는 코드만으로 의도가 드러나지 않는 이유나 제약을 적는다.
- 제약을 설명할 때는 제약의 주체와 어겼을 때 나타나는 증상을 함께 적고, 외부 주체는 이름으로 지목한다.
- 이름, 시그니처와 코드가 이미 말하는 내용은 되풀이하지 않는다.
- 현재 코드의 이유와 제약에 대한 설명을 `SPEC §5.N`, `DESIGN §X.Y`, `task-<nnn>` 같은 계획 문서 식별자나
  작업 단계, 변경 경위와 이력으로 대신하지 않는다.
- 라이선스 헤더, 생성 코드 표식, formatter·linter·type checker 지시문은 설명 주석과 구분하고 해당 도구와 프로젝트 규칙을 따른다.
- 코드를 고치면 영향받는 기존 주석의 정확성을 확인하고, 어긋나면 고치거나 지운다.

## 언어별 문서
- Go 파일을 수정하거나 검토할 때는 `languages/go.md`를 읽고 적용한다.
- C# 파일을 수정하거나 검토할 때는 `languages/csharp.md`를 읽고 적용한다.
- JavaScript 또는 TypeScript 파일을 수정하거나 검토할 때는 `languages/javascript-typescript.md`를 읽고 적용한다.
