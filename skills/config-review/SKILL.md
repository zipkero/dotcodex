# Config Review

## 목적
- 지정된 설정 파일 또는 전역 설정을 변경하지 않고 감사한다.
- 정책을 다시 정의하지 말고, 각 권위 문서가 소유한 역할·책임·흐름이 서로 일치하는지 확인한다.
- 과도한 범위, 빠진 판단 기준, 책임 충돌, 중복과 현재 Codex 실행 방식에 맞지 않는 전제를 찾는다.

## 컨텍스트 로딩
- 특정 파일이나 skill 감사에서는 대상과 판단에 직접 필요한 권위 문서·참조만 읽는다.
- 전역 감사에서는 `AGENTS.md`, 루트 `README.md`, `.gitignore`, `.editorconfig`, `.gitattributes`, `docs/**`, 관리 대상 `agents/*.toml`,
  `skills/*/SKILL.md`와 존재하는 `skills/*/agents/openai.yaml`을 읽는다.
- 실제 관리 범위는 `.gitignore` 문구만으로 추정하지 말고 `git ls-files`, `git check-ignore` 등 Git 결과로 확인한다.
  예외적으로 추적되는 설정 집합은 `추적 허용 목록`으로 표현한다.

## 외부 기준 사용
- 공식 문서는 설정 스키마, 탐색 경로, 에이전트 호출, 권한처럼 버전에 따라 달라지는 제품 동작을 확인할 때만 사용한다.
  OpenAI 제품 동작은 `openai-docs`를 통해 최신 공식 자료를 확인하고 게시일과 적용 대상을 함께 본다.
- 로컬 역할 분리, 정책 소유권과 작업 흐름은 사용자 목적 및 로컬 권위 문서를 기준으로 판단한다.
- 현재 환경에서 확인한 동작과 공식 지원 범위·다른 환경으로의 이식 가능성을 구분해 보고한다.
  둘이 다르면 관찰 결과를 공식 보장처럼 일반화하지 않는다.
- 중복, 모호한 표현, 파일 소유권과 로컬 정합성처럼 파일만으로 판단할 수 있는 항목에는 외부 조회를 요구하지 않는다.

## 감사 기준

### 역할과 권한
- 각 역할의 목적, 책임·제외 범위, 입력, 판단·근거·중단·인수인계 기준, 성공 조건과 출력이 소유한 결정에 맞게 실행 가능한지 확인한다.
  핵심 기준이 빠지면 `부족`, 충분하지만 내부 중복·과도한 절차나 반복 출력이 있으면 별도로 `과함`을 판정한다.
- 파일 수정, 사용자 확인, 상태 전환과 최종 승인·거절의 권한이 구분되고 main의 최종 권한이 agent나 skill로 넘어가지 않는지 확인한다.
- 전역 원칙과 작업 분류는 `AGENTS.md`, 역할별 실행 절차와 산출물 규약은 해당 skill,
  사용자 정의 하위 에이전트의 역할·실행 특성은 해당 agent 설정이 소유하는지 확인한다.
- 상위 권위 문서에서 상속되는 기준을 반복하거나 다른 역할의 정책을 재정의·대체하지 않는지 확인한다.
- 다른 역할이나 skill을 언급·호출·인계하는 것만으로 역할 침범으로 판단하지 않고,
  실제 권위 문서와 호출 관계에서 판단·실행·수정 권한을 가져왔는지 확인한다.
- agent와 skill 메타데이터의 필수 필드, 모델·추론·권한 설정과 지침 언어가 현재 Codex 형식 및 실제 역할에 맞는지 확인한다.
- `SKILL.md` frontmatter의 `description`과 `agents/openai.yaml`의 표시·기본 프롬프트·호출 정책·도구 의존성도 실제 역할과 호출 조건에 맞아야 한다.

### 흐름과 상태
- `Per-Request`와 사용자가 선택한 `Phased(문서 우선)`의 진입 기준이 권위 문서 사이에서 일치하는지 확인한다.
- 작성과 독립 검증이 분리되고 각 단계의 선행 조건, 재진입, 중단, 상태 전환과 다음 단계가 모순 없이 이어지는지 확인한다.
- 구현 품질, 테스트, 주석과 문서 산출물 기준은 담당 skill이 소유하고 인접 문서가 이를 다르게 재정의하지 않는지 확인한다.
- 흐름이 중간에 끊겨도 승인된 문서와 현재 상태만으로 재개할 수 있고, 미해결 판단이 대화 기억에만 남지 않는지 확인한다.

### 문구와 컨텍스트
- 의미 충돌, 모호함, 중복, 불필요한 부정형, 폐기된 설명과 역할 밖 정책을 찾고 조건·예외·권한·중단 기준을 보존하며 압축할 수 있는지 확인한다.
- agent 사용 기준과 호출 계약, 범위와 실행 규칙, 완료 보고와 반환 형식, 판단 절차와 상태 전환처럼 인접 섹션이 같은 조건·근거·결과를
  반복하는지 확인하고, 독립적인 판단이나 행동을 추가하지 않는 항목은 묶는다.
- 비슷한 표현이라도 적용 시점·주체·강도·입력·근거·출력이 다르면 별도 행동으로 보고 보존한다.
- 성능 영향은 질문 빈도·중단 시점·변경 범위처럼 관찰 가능한 행동을 근거로 판단한다.
- `AGENTS.md`가 특정 skill의 절차를 과도하게 설명하거나 같은 역할 지침이 여러 문서에 반복되면 컨텍스트 저하 신호로 본다.
- 인코딩·줄바꿈·적용 범위 기준이 `AGENTS.md`, `.editorconfig`, `.gitattributes` 사이에서 일치하는지 확인한다.
- README는 권위 문서가 아니며 실제 구조·역할·기능 설명, 파일과 링크의 현재 정확성만 점검하고 제안이 설명에 영향을 줄 때만 동기화를 보고한다.

## 판단 방법
- 현재 설정과 비교해 실제 행동, 판단 명확성 또는 유지보수성이 나아질 때만 변경을 제안한다.
- 명확한 규칙을 모호하게 만들거나 이론적 유연성만 늘리는 제안과 선호·일반론만 근거로 한 문구 변경은 제외한다.
- 압축 제안은 주체, 조건, 행동, 중단, 근거와 출력이 명시적으로 남는지 확인하고 보존되는 의미와 줄어드는 표현을 설명한다.

## 출력
- 요약과 확인한 범위
- 전체 판정: `정상`, `과함`, `부족`, `충돌`을 해당하는 만큼 복합 병기한다.
- 역할 프롬프트 판정: 전역 요약과 역할별 `충분`, `부분 부족`, `부족`을 구분하고, 해당하면 `과함`을 함께 표시한다.
- 우선순위별 발견 사항
  - 중요한 발견은 위치·근거, 행동 영향, 변경 실익, 제안 방향과 영향받는 파일을 포함한다.
  - 경미한 표현이나 반복은 성격과 제안이 같은 항목끼리 묶어 간결히 보고한다.
  - 행동 문제와 별개로 의미를 보존하며 실질적으로 줄일 수 있는 압축 후보는 낮은 우선순위라는 이유만으로 생략하지 않는다.
  - README 동기화는 실제 영향이 있는 발견에만 적는다.
- 발견 사항이 없으면 그 사실과 남은 검증 한계를 적는다.

## 제외
- 요청 없는 파일 수정
- 새 정책 체계나 작업 흐름 설계
- 로컬 권위 문서보다 외부 일반론을 우선한 역할 재편
