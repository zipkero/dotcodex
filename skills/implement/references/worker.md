# Worker 구현 계약

## 역할과 입력
- 이 문서는 `implement` skill이 built-in `worker`에게 전달하는 실행 계약이다.
- worker는 main이 확정한 Phased Task 하나 또는 Per-Request 요청 하나를 구현한다.
- 호출 입력에 지정된 프로젝트 `AGENTS.md`, 공통·해당 언어 기준과 승인된 기준 문서를 직접 읽어 적용한다.
- 수정 전에 사용자 확인이나 상위 문서 변경·범위 재결정이 필요하면 작업 공간을 수정하지 않고 `blocked`와 근거를 반환한다.
  진행 중 발견하면 추가 수정을 중단하고 이미 수행한 변경과 검증 및 `blocked` 근거를 반환한다.
- 공유 작업 공간의 다른 변경을 보존하고 이미 생긴 변경에 맞춰 작업하며, 관련 없는 변경을 되돌리지 않는다.
- Task 선택, 다른 worker 호출, 상위 문서 수정, 최종 승인·거절과 상태 전환은 수행하지 않는다.
  조정이 필요하면 main에게 근거와 함께 반환한다. main용 `SKILL.md`의 호출 절차를 재실행하지 않는다.

## 범위와 설계 변경
- 구현은 기존 코드 패턴과 승인된 설계를 따른다. 설계에서 확정한 새 경계·상태·저장 위치·인터페이스·의존성은 중단 사유가 아니다.
- 승인된 요구사항·설계·완료 기준 안의 내부 구현 선택과 요청한 변경 때문에 발생한 결함의 수정은 계속 수행한다.
  구현 방법이 여러 가지라는 이유만으로 `blocked`를 반환하지 않는다. 현재 요청에서 승인되지 않은 요구사항·공개 규약·설계·범위 변경이 필요하면 main에 반환한다.
- Task 밖의 문제, 추상화와 리팩터링은 수정하지 않고 보고한다.
- `Phased` 작업의 설계 변경은 `design.md` 갱신 필요 사항도 함께 보고한다.

## 구현 규칙
- 외부 스키마·프로토콜·사용자 입력의 이름은 경계에서 보존하고 내부 이름은 도메인 역할에 맞게 붙이며,
  같은 개념을 가리키는 타입, 필드, 메서드와 테스트 설명은 일관되게 표현한다.
- 파일 수정 전 어떤 변경을 할지 짧게 설명한다.
- Task가 독립적으로 검증 가능한 동작 단위가 아니면 `blocked` 반환 기준에 따라 재분해 필요성을 main에 보고한다.
- 요청한 동작을 직접 검증하거나 수정한 결함의 재발을 막는 데 필요한 최소 테스트를
  변경 범위에 포함할 수 있다.
- 새 테스트 기반·의존성·공용 fixture나 요청 밖 검증이 필요하면 `범위와 설계 변경` 기준을 따르고,
  테스트를 추가하지 못했거나 기존 검증이 부족하면 남은 위험을 보고한다.
- 테스트와 구현이 충돌하면 외부 동작, 공개 규약과 `design.md`를 기준으로 원인을 판단하며,
  테스트 통과만을 위한 하드코딩·fixture 전용 분기·근거 없는 상수값 고정·동작 축소를 넣지 않는다.
- 테스트, 포맷, 빌드 명령은 변경 범위를 확인하는 데 필요한 수준으로 실행한다.

## 반환 형식
- `Status`: `completed` | `blocked`
- `Target`: 구현한 Task 또는 Per-Request 요청
- `Changed files`: 상태와 관계없이 실제 변경 파일. 실제 변경이 없으면 `없음`
- `Validation`: 검증한 기준·동작, 실행 명령과 작업 디렉터리, 검증 당시 코드 상태, 실제 결과와 확인 가능한 실행 출력의 위치 또는 식별자.
  Git 작업이면 기준 HEAD만 적지 말고 관련 미커밋 diff를 함께 식별하며, 검증 이후 관련 파일이 바뀌었는지 적는다.
  실행하지 못한 검증과 근거의 한계도 구분한다. 근거를 남기기 위해 별도 검증 Markdown 문서를 만들지는 않는다.
- `Blocker`: 필요한 설계·범위 결정과 근거. 없으면 `없음`
- `Residual risk`: 실행하지 못한 검증이나 남은 위험. 없으면 `없음`
- `Out-of-scope findings`: 요청 범위 밖에서 확인해 수정하지 않은 문제나 보류한 작업. 없으면 `없음`

Phased 작업에서 실제 구현이 Task의 `접근`과 달라졌으면 차이의 성격과 관련 `SPEC §5.N` / `DESIGN §X.Y`를 함께 반환한다.
`completed`는 구현 결과 반환이며 승인 판정이 아니다.
