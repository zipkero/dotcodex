# 공통 구현 기준

worker는 구현·실행 검증에, main은 위임·결과 검토에 적용한다. Phased는 승인된 `spec.md`, `design.md`와 Task 기준도 적용한다.

## 범위와 구현
- 원본·지침·승인 기준을 직접 읽고 기존 패턴을 따른다. 승인 범위 안의 구현 선택과 결함 수정은 계속하며 승인된 새 경계·상태·저장 위치·인터페이스·의존성은 중단 사유가 아니다.
  승인된 요구 동작을 막는 결함은 기존부터 있었어도 수정할 수 있지만, 이 기준이 관련 없는 결함이나 범위 확대를 허용하지는 않는다.
- 승인되지 않은 요구사항·공개 규약·설계·범위 변경은 중단한다. main은 사용자 판단을 받고 worker는 근거를 반환한다. 범위 밖 수정·추상화·리팩터링도 하지 않는다.
- 외부 이름은 경계에서 보존하고 내부 이름과 테스트 설명은 도메인 개념에 맞춰 일관되게 쓴다.
- 코드는 `~/.codex/docs/languages.md`와 해당 언어 기준을 직접 적용하고, 더 구체적인 프로젝트 지침과 도구 설정을 우선한다.

## 테스트와 검증
- 동작 검증과 재발 방지에 필요한 최소 테스트를 포함할 수 있다. 새 테스트 기반·의존성·공용 fixture나 범위 밖 검증이 필요하면 중단 기준을 따르고 한계를 보고한다.
- 구현·검증 실패는 판정에 필요한 범위에서 제품·테스트·환경 원인과 사용자 영향을 조사한 뒤 필요한 수정 단계를 선택한다.
  실제 사용 조건에서 요구 동작의 불충족이 확인되면 정확한 원인이 아직 확정되지 않았다는 이유로 완료 처리하지 않는다.
- 테스트 충돌은 승인 요구사항·공개 규약·기존 동작을 기준으로 판단한다.
  하드코딩·fixture 전용 분기·근거 없는 상수·동작 축소·assertion 약화로 통과시키지 않는다.
- 필요한 테스트·포맷·lint·빌드를 실행하고 결과를 기준과 당시 코드 상태에 연결한다. 미실행 검증과 남은 위험은 구분해 보고한다.
