# Cross Analyze

## 목적
- 하나의 질문을 여러 subagent가 같은 입력으로 독립 분석하게 하고, main이 근거를 교차검증해 결론을 합친다.
- 구현이나 파일 변경으로 확장하지 않고 분석 결과만 대화로 보고한다.

## 입력
- 실행 프롬프트에 agent 수가 명시되어 있으면 그 수를 사용한다. 허용 범위는 3~5개다.
- agent 수가 명시되어 있지 않으면 기본값인 3개를 사용한다.
- 명시된 수가 3~5 범위를 벗어나면 임의로 보정하거나 실행하지 말고, 허용 범위를 안내한 뒤 3~5 중 하나를 요청한다.
- 질문이 비어 있고 대화에서 단일한 미해결 분석 질문을 식별할 수 없으면 분석 대상을 확인한다.
- 동시 실행 한도보다 많은 agent를 요청하면 가능한 수만큼 배치로 나눈다.
  요청한 전체 호출의 성공 또는 실패가 확정된 뒤 결과를 종합한다.

## 위임
- 사용자가 이 skill을 명시적으로 선택하면 아래 `default` agent 독립 분석 구성이 `AGENTS.md`의 일반 `explorer` 라우팅보다 우선한다.
- built-in `default` agent를 사용하고 `fork_turns = "none"`으로 호출한다.
- 모델과 추론 수준은 따로 재정의하지 않고 부모 설정을 상속한다.
- 모든 agent에 문구까지 같은 자체 완결적 프롬프트를 전달한다. 프롬프트에는 다음 내용을 포함한다.
  - 답해야 할 질문과 필요한 하위 질문
  - 알고 있는 핵심 파일·심볼의 절대 경로
  - 코드를 직접 읽고 주요 주장에 `file:line` 근거를 붙일 것
  - 확인 사실과 추정을 구분할 것
  - 파일을 만들거나 수정하지 않을 것
  - 결론을 먼저 제시하고 사용자 결정이 필요한 지점을 보고할 것
- 모든 agent 호출과 필요한 재시도가 끝날 때까지 기다린다.
  main은 같은 범위를 전면 재분석하지 않는다.

## 실패 처리
- 호출 실패, 빈 결과 또는 필수 근거 누락은 같은 프롬프트로 한 번만 재시도한다.
- 재시도에도 실패하면 해당 agent를 실패로 기록하고 나머지 결과로 진행한다.
- 요청 수, 유효 결과 수와 실패 수를 구분해 보고한다.
- 유효 결과가 2개 미만이면 합의로 표현하지 않고 `교차검증 불충분`으로 보고한다.

## 교차검증
- 같은 결론에 도달한 agent 수와 공통 근거를 표시한다.
- 결론이 갈리면 각 주장과 근거를 숨기지 않고, main이 결정적인 `file:line`만 직접 확인해 판정한다.
- 한 agent만 찾은 내용도 근거가 확인되면 단독 발견으로 채택한다.
- agent가 지정 대상을 찾지 못했거나 다른 근거로 대신했으면 그 한계를 밝힌다.
- `M/N`에서 `M`은 같은 결론에 도달한 유효 결과 수, `N`은 전체 유효 결과 수다.
  요청 수와 실패 수는 별도로 표시하며, `M/N`은 정확도 확률이 아니다.

## 출력
- 요청 수, 유효 결과 수와 실패 수
- 결론과 합의 수
- 합의 사항과 공통 근거
- 불일치와 main의 판정 근거
- 근거가 확인된 단독 발견
- 확인 사실과 남은 추정
- 필요한 사용자 결정 또는 다음 조사 대상

불일치나 단독 발견처럼 해당하지 않는 항목은 생략한다.
