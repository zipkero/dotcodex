# Explain

## 역할
- 지정된 코드·변경·Task·시스템을 읽기 전용으로 설명해 사용자가 동작과 그 맥락을 이해하도록 돕는다.
- 원인 조사나 새 설계 판단은 `analyze`, 구현과 정식 판정은 해당 skill의 역할이다.

## 근거 확인
- 요청한 대상과 앞뒤 연결을 파악하는 데 필요한 원본 문서, 현재 코드, 호출부, 관련 미커밋 diff, 테스트와 실행 근거를 확인한다.
- 저장된 실행 근거는 현재 코드와 대응하는지 확인한다. 새 실행은 설명에 필요한 읽기 전용 범위에서만 수행한다.
- 확인한 동작과 추론을 구분하고, 설계 이유는 문서나 코드에서 확인되는 범위로 한정한다.

## 설명 구성
1. **출발점과 변화:** Task·변경 설명은 이전까지 가능한 동작 → 남아 있던 문제 → 이번에 추가하거나 바꾼 규칙 순서로 시작한다. 전체 맥락은 이번 변화를 이해하는 데 필요한 만큼 연결한다. 그 밖의 대상은 목적과 전체 흐름 속 위치부터 설명한다.
2. **대표 동작:** 대표 사례 하나를 따라 입력·처리·상태·출력이 어떻게 달라지는지 설명한다.
3. **구현과 선택 이유:** 새 규칙이 실제 코드의 어디에 연결되는지 보여주고, 주요 구현 선택의 이유를 확인된 근거 범위에서 설명한다. 세부 기법은 그 역할이 등장하는 지점에서 풀어 쓴다.
4. **예외와 경계:** 기본 동작을 설명한 뒤 주요 실패 경로·경계 조건·제약과 기존 기능의 상호작용을 설명한다.
5. **근거와 한계:** 설명 가까이에 파일·심볼 링크와 필요한 코드 발췌를 둔다. 확인하지 못한 부분과 이유를 밝힌다.

## 표현과 시각화
- 배경지식은 사용자의 질문에 맞추고, 별도 정보가 없으면 전문용어는 첫 등장 때 뜻을 풀어 쓴다. 식별자나 코드를 제시하기 전에 역할을 일상적인 말로 설명한다.
- 여러 단계나 구성 요소의 연결은 설명 목적에 맞는 텍스트 다이어그램으로 보여주고 요청한 대상을 표시한다.
- 코드 동작은 실제 파일·함수명과 호출 순서가 드러나는 텍스트 다이어그램으로 보여준다. 주요 분기·반복·복귀 지점을 포함하고, 호출 트리 등 이해하기 쉬운 형식을 선택한다.
- 다이어그램과 본문의 명칭과 흐름을 맞추고, 변경 전후나 여러 대상의 차이는 표로 비교한다.
- 제목과 분량은 질문에 맞추고, 요청한 부분을 중복 없이 상세하게 설명한다.
