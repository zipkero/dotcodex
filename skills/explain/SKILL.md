# Explain

## 목적과 경계
- 사용자가 코드를 모두 읽지 않아도 시스템을 이해하고 후속 변경과 장애 대응을 판단할 수 있도록 목적, 흐름, 계약과 가정, 결정과 트레이드오프, 근거의 신뢰도와 한계, 이후 조사 지점을 설명한다.
- 대상 파일·설정·문서·체크리스트·상태를 읽기 전용으로 조사한다. 사용자가 설명 기록 파일을 명시적으로 요청한 경우에만 그 파일을 작성하며, 구현 수정·정식 승인/거절·상태 전환은 하지 않는다.
- 설명을 정확하게 만들기 위한 내부 조사와 분석은 수행할 수 있다. 요청 산출물이 원인 규명, 구조·대안 판단이나 새 설계 제안이면 `analyze`를 사용하고, 기존 코드·변경·시스템이 무엇이고 어떻게 작동하는지 이해시키는 설명이면 이 skill을 사용한다. `analyze`·`verify` skill이나 agent를 자동 호출하지 않는다.

## 대상 확정과 조사
- 요청과 대화에서 대상을 식별한다. 대상은 Phased Task, Milestone이나 기능, Per-Request 변경, commit·diff·파일·함수, 기존 시스템일 수 있다.
- 결과를 바꾸는 모호함만 질문한다. 저장소·기능 문서·Git 상태에서 확인할 수 있는 범위와 사실은 먼저 조사한다.
- 질문에 필요한 요구사항, 설계, 현재 코드와 미커밋 변경, 호출부, 테스트, 실행 근거를 선택해 읽는다. 문서의 설명을 현재 구현과 대조한다. 같은 HEAD만으로 실행 당시와 현재 코드가 같다고 보지 않으며, 미커밋 변경을 포함해 테스트 후 관련 코드가 바뀌었다면 이전 결과를 현재 코드의 증거로 사용하지 않는다.
- 새 실행은 설명의 중요한 불확실성을 줄이는 데 필요하고 현재 권한과 부작용 범위 안일 때만 수행한다. 설명을 위해 운영 환경 호출이나 배포를 실행하지 않는다.

## 설명 구성
- 결론과 사용자 영향부터 제시하고, 대표 입력이나 시나리오를 따라 책임과 데이터 흐름을 연결한다. 파일별 diff 나열보다 경계에서 무엇이 들어와 어떤 결정과 변환을 거쳐 무엇이 나오는지 설명한다.
- 확인한 사실, 문서에 기록된 이유, 근거에서 추론한 의도, 검증되지 않은 가정, 당시 실제로 검토된 대안, 이번에 새로 제안하는 대안을 구분한다. 근거가 없는 이유나 역사적 대안을 만들어내지 않는다.
- 중요한 결정과 계약은 실제 코드나 문서의 간결한 발췌와 파일·함수 링크로 보여 주고, 각 발췌가 무엇을 증명하는지 설명한다. 중요한 주변 맥락을 생략해 오해를 만들지 않으며, 더 읽어야 하면 위치·읽을 범위·확인할 질문을 구체적으로 적는다. 의사코드는 의사코드라고 표시한다.
- 입력 경계, 핵심 결정, 테스트 근거가 설명에 중요하면 서로 연결한다. 테스트는 이름이나 통과 목록 대신 입력·조건·assertion·실제 관찰과 한계를 설명하고, 코드상 테스트 존재와 실제 실행 결과를 구분한다.
- 관련 영향, 계약, 호환성, 트레이드오프를 비판적으로 평가한다. 데이터베이스, 동시성, transaction, cache, retry, timeout, 운영과 rollback은 대상에 실제로 관련될 때만 다룬다.
- 확인된 결함은 영향과 근거를 앞세워 보고한다. 근거 있는 실패 가능성은 재현이 확인된 결함과 구분하고, 각각의 반례를 현재 테스트가 다루는지와 남은 검증 한계를 설명한다. 검증되지 않은 우려를 채우기식으로 추가하지 않는다.

대상 성격에 맞게 설명의 관점을 조정한다.

- 버그: 증상, 발생 조건, 원인, 잘못된 가정, 수정 전후 동작, 재현과 회귀 근거를 연결한다.
- 기능: 필요와 새 동작, 설계 선택과 영향을 설명하되 확인되지 않은 근본 원인을 만들지 않는다.
- 기존 구조: 책임, 경계 계약, 데이터 흐름과 실패 방식을 설명하며 억지로 변경 서사를 만들지 않는다.
- Milestone이나 기능: 전체 시나리오를 중심으로 현재 가능한 동작, 그 근거, 남은 공백과 선행 조건을 설명한다. Task 설명을 이어 붙이거나 공식 완료를 선언하지 않는다.

## 결과
- 한국어로 결론과 핵심 근거를 먼저 쓰고, 사용자가 대상을 운영·수정·추가 조사할 때 필요한 수준으로 구조를 유연하게 정한다. 흐름이나 책임 관계가 복잡할 때만 간결한 흐름도를 사용한다.
- 근거마다 현재 코드·문서·diff·실행 결과로 연결되는 위치를 제공한다. 확신 수준과 근거의 한계, 현재 테스트가 보장하는 범위, 후속 조사 위치를 명확히 한다.
- 설명 가치가 높은 발췌와 위치를 선택하되 고정 개수나 분량 제한을 두지 않고, 중복 원문 덤프는 피한다. 마지막에는 가장 기억해야 할 동작·계약·위험을 짧게 남긴다.
