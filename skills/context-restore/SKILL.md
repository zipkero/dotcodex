# Context Restore

## 역할
- 프로젝트 루트의 `CONTEXT.md`를 원본 문서와 현재 작업 트리에 대조해 읽기 전용으로 복원한다.
- Phased의 요구사항·설계·Task 상태는 기능 문서를, Per-Request는 저장된 범위와 현재 작업 트리를 기준으로 한다.

## 절차
1. `CONTEXT.md` 전체를 읽는다.
   없으면 저장된 맥락이 없다고 보고한다.
2. 현재 작업 문서, 확정된 결정, 문서 반영 필요, 필수·변경 파일을 읽는다.
   조건부 파일은 조건이 해당할 때만 읽는다.
   저장된 실행 근거가 현재 코드와 대응하지 않으면 재검증 필요로 보고한다.
3. `현재 상태`에 적힌 worker·background 작업의 결과를 받을 위치가 현재도 존재하거나 접근 가능한지 확인한다.
4. Git 저장소이면 저장된 branch·기준 HEAD·커밋 안 된 변경 파일과 상태를 현재 `git status`와 실제 변경에 대조한다.
   HEAD가 달라졌으면 `git log <기준 HEAD>..HEAD`의 커밋 수를 함께 보고한다.
   기준 HEAD를 조회할 수 없으면 커밋 수는 확인 불가로 보고한다.
5. 저장 시각과 현재 시각의 차이를 계산하고, 7일 이상 지났으면 오래된 맥락일 수 있다고 경고한다.
6. §복원 보고의 항목으로 결과를 보고한다.

## 복원 보고
- 저장값이 `없음`이면 `없음`, 항목이 비었거나 복원할 근거를 찾지 못했으면 `저장 안 됨`으로 보고한다.

1. 현재 목표
2. 저장 시점과 경과, 현재 상태와 현재 작업 문서
3. 확정된 결정
4. 작업 제약
5. 미확정 판단
6. 시도했지만 실패한 접근
7. 대기 중인 사용자 응답
8. 저장된 다음 작업과 완료 기준
9. 문서 반영 필요
10. 누락되거나 원본 문서·작업 트리와 어긋난 맥락

## 경계
- 다음 작업 실행도 요청받았으면 복원한 작업 제약과 대기 상태를 적용해 `AGENTS.md`와 해당 skill로 진행한다.
  `이어서 진행` 요청도 같은 기준으로 처리하며, 답이 필요한 대기 중인 질문·승인 요청은 해당 응답을 받은 뒤 의존 작업을 진행한다.
- 원본 미반영 결정이 다음 작업의 선행 계약이면 의존 작업 전에 해당 문서 소유 단계에서 해소한다.
