# Context Restore

## 목적
- 프로젝트 루트의 `CONTEXT.md`를 원본·작업 트리와 대조해 저장된 맥락을 읽기 전용으로 복원한다.

## 적용 경계

- Phased 문서가 있으면 Task 상태, 요구사항과 구현 체크리스트는 해당 문서를 기준으로 복원한다.
- Phased 문서가 없는 Per-Request 맥락은 저장된 요청 범위와 현재 작업 트리를 기준으로 복원한다.
- `CONTEXT.md`는 작업을 중단시킨 설계 변경, 현재 논점과 다음 작업을 보완한다.
- `저장` 시각은 참고 정보이며 충돌의 우선순위나 최신 결정의 근거가 아니다.

## 복원 절차

1. 프로젝트 루트의 `CONTEXT.md`를 전체 읽는다. 없으면 저장된 맥락이 없다고 알리고 재구성하지 않는다.
2. `저장`이 없으면 이전 형식의 `저장 시점 없음`으로 보고한다.
   `현재 목표`, `현재 상태`, `다음 작업` 또는 완료 기준이 누락됐으면 누락된 내용을 기록하고 추정으로 채우지 않는다.
3. `현재 작업 문서`, `확정된 결정`, `문서 반영 필요`의 원본과 `먼저 읽을 파일`의 필수·변경 파일을 읽는다.
   조건부 참고 파일은 저장된 다음 작업에 조건이 해당할 때 읽고, 해당 여부를 판단할 수 없으면 읽어 확인한다.
   현재 목표·상태·확정된 결정·문서 반영 필요를 검증할 원본과 실제 변경 파일은 조건부 표시가 있어도 생략하지 않는다.
   읽지 않은 조건부 참고는 파일 내용·존재·최신성을 검증한 것으로 보고하지 않는다.
   조건 표기가 없는 기존 목록은 모두 읽는다. `먼저 읽을 파일`이 없고 `먼저 읽을 문서`만 있으면 이전 형식으로 보고 같은 항목으로 읽는다.
4. Per-Request 맥락이면 저장된 변경 파일의 존재와 현재 내용을 확인한다.
   대상이 Git 저장소이면 저장된 branch·기준 `HEAD`와 현재 `git status`를 대조한다.
   `HEAD`가 저장 시점과 다르다는 사실만으로 충돌로 판정하지 않는다.
   저장된 변경이 사라졌거나 파일 상태가 설명과 어긋나면 차이를 보고한다.
5. 누락·불일치를 먼저 보고한다. `문서 반영 필요`에 없는 충돌은 현재 원본을 기준으로 복원한다.
   `문서 반영 필요`는 원본 미반영 확정 사항으로 보존하되 원본과 충돌하면 양쪽을 보고하고 현재 결정은 사용자 판단 사항으로 남긴다.
6. 아래 형식으로 보고한다. 원본의 미합의 구현 제안은 `미확정 판단`과 분리해 `관련 참고`로 짧게 소개한다.
   복원 단계에서 기술 대안을 확장하거나 사용자에게 선택을 요구하지 않는다.

## 복원 후 경계

- 복원만 요청받으면 파일·상태를 변경하지 않고 보고로 종료한다.
- 사용자가 다음 작업의 실행까지 명시하면 복원을 마친 뒤 `~/.codex/AGENTS.md`의 `문서 우선 흐름`과 해당 skill을 따라 진행한다.

## 복원 보고

다음 순서로 간결하게 보고한다.

1. 현재 목표
2. 저장 시점, 현재 상태, 현재 작업 문서와 먼저 읽을 파일
3. 확정된 결정
4. 미확정 판단
5. 저장된 다음 작업과 완료 기준
6. 누락되거나 원본 문서·현재 작업 트리와 충돌한 맥락, 읽지 않은 조건부 참고와 그 조건이 있으면 해당 내용
7. 관련 참고가 있으면 합의 여부와 함께 짧게 소개
