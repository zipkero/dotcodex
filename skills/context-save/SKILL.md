# Context Save

## 목적

- 프로젝트 루트의 `CONTEXT.md`만 인수인계 진입점으로 사용해 현재 작업의 위치를 다음 Codex 세션이 대화 기록 없이 복원할 수 있게 저장한다.
- 확정된 설계 원문은 기존 프로젝트 문서에 두고, `CONTEXT.md`에는 결정 이력 대신 현재 초점·상태와 링크만 남긴다.

## 적용 경계

- Phased 문서가 있으면 Task 상태, 요구사항과 구현 체크리스트는 해당 문서를 기준으로 삼고,
  `CONTEXT.md`에는 체크리스트를 복제하지 않고 작업을 중단시킨 변경, 현재 논점, 이어서 볼 문서와 다음 작업만 기록한다.
- Phased 문서가 없는 Per-Request 작업은 사용자 요청 범위, 실제 변경 파일과 실행한 검증 결과를 기준으로 기록한다.
- `context-save`는 `CONTEXT.md`만 변경한다.
  원본 문서에 반영되지 않은 확정 사항은 `문서 반영 필요`에 기록하고 해당 문서를 소유한 skill로 넘긴다.
- 사용자가 명시적으로 요청했을 때뿐 아니라 문서 작성·구현 중 단계 완료, worker 결과 인수 또는 중단으로 기존 원본만으로 재개할 수 없는 상태가 바뀌었을 때 main이 적용한다.
  사용자 판단 대기, `blocked`, agent 호출 실패, 재시도 한도 소진으로 멈추면 원인, 현재 변경, 마지막 검증과 재개 조건을 저장한다.
- 매 응답마다 저장하지 않는다. 읽기 전용 `analyze`·`explain`·검토·복원은 사용자가 저장을 요청하지 않는 한 자동 적용하지 않는다.
- spec 요구사항이 미확정이면 `spec.md`를 확정하거나 승인하지 않고 확인 사실과 사용자 질문을 저장한다.

## 저장 절차

1. 프로젝트 루트의 기존 `CONTEXT.md`가 있으면 전체를 읽는다.
2. 현재 대화, 원본 문서와 작업 트리를 대조해 §CONTEXT.md 형식에 필요한 내용을 확인한다.
3. 기존 파일이 명백히 다른 활성 주제를 다루면 덮어쓰지 않고 사용자에게 저장 위치를 확인한다.
4. 같은 주제이면 현재 인수인계에 필요한 내용으로 교체하고, 원본 반영·해결·폐기·대체로 불필요해진 항목은 제거한다.
5. 활성 목표, 미확정 판단, 다음 작업과 문서 미반영 사항이 모두 없으면 삭제 근거를 설명하고 사용자 확인을 받은 뒤
   기존 `CONTEXT.md`를 삭제하고 종료한다.
6. 다음 구현 작업을 아직 확정할 수 없으면 사용자 결정 대기와 확인할 질문, 그 결정 뒤의 작업을 `다음 작업`에 기록한다. 불명확한 다음 단계만을 이유로 저장을 보류하지 않는다.
7. `apply_patch`로 프로젝트 루트의 `CONTEXT.md`를 작성한다.

## CONTEXT.md 형식

```markdown
# Context

저장: <yyyy-MM-dd HH:mm zzz>

## 현재 목표

## 현재 상태

## 현재 작업 문서

## 확정된 결정

## 미확정 판단

## 다음 작업

- 작업:
- 완료 기준:

## 먼저 읽을 파일

## 문서 반영 필요
```

다음 기준으로 내용을 채운다.

- `저장`은 현재 지역 시각과 UTC offset을 `yyyy-MM-dd HH:mm zzz` 형식으로 적는다.
- `현재 목표`는 이번 작업이 도달하려는 결과와 사용자가 요청한 범위를 간결하게 적는다.
- `현재 상태`는 마지막으로 완료한 의미 있는 작업과 그 결과, 현재 멈춘 지점을 적되 세부 작업 이력은 나열하지 않는다.
  멈춘 원인이 아직 해소되지 않은 문제면 문제와 해소 조건을 함께 적는다.
  중단 전에 생긴 부분 변경과 worker 결과 인수 여부를 적는다.
  마지막 주요 검증과 결과를 덧붙이고, 실행한 검증이 없으면 `실행하지 않음`으로 적는다.
  Per-Request 작업이 Git 저장소에서 수행됐다면 저장 시점의 branch와 기준 `HEAD`를 적는다.
  해당하지 않는 상태 항목은 생략한다.
- `현재 작업 문서`에는 활성 기능과 Task가 있으면 그 문서와 Task를 링크한다.
  Per-Request 작업이거나 활성 문서가 없으면 `없음`으로 적는다.
- `확정된 결정`에는 사용자가 확정했거나 프로젝트 문서에서 확인한 내용 중 다음 작업을 직접 제약하는 것만 적는다.
- `미확정 판단`에는 다음 결과를 실질적으로 바꿀 선택지만 적는다.
- 원본 문서에만 있는 미합의 구현 제안은 `미확정 판단`으로 옮기지 않는다.
  다음 작업을 이해하는 데 필요하면 `현재 상태`에 합의되지 않은 참고임을 밝혀 짧게 남긴다.
- `다음 작업`에는 새 세션이 바로 시작할 작업 하나와 검증 가능한 완료 기준을 적는다. 사용자 판단을 기다리면 확인할 결정과 결정 뒤의 작업을 적는다.
- `먼저 읽을 파일`에는 다음 작업에 필요한 원본 문서와 변경 파일 경로를 적는다.
  `CONTEXT.md`의 파일 참조는 프로젝트 내부 파일이면 프로젝트 루트 기준 상대 링크로, 전역 설정과 보조 문서이면 인라인 코드 `~/.codex/...`로 적는다.
  변경 파일 경로는 이 항목에만 둔다.
  각 항목에는 `필수`, `변경 파일` 또는 `조건부: <읽는 조건>`과 읽는 이유를 적는다.
  현재 목표·상태·확정된 결정·문서 반영 필요를 검증할 원본과 실제 변경 파일은 조건부로 돌리지 않는다.
  특정 후속 작업에서만 필요한 참고 파일만 조건부로 표시하며, 관련 없는 문서 목록을 늘리지 않는다.
- `문서 반영 필요`에는 확정됐지만 원본 또는 Phased 문서에 아직 반영되지 않은 내용만 적고, 없으면 `없음`으로 적는다.

## 제외할 내용

- 대화 전문, 긴 요약, 전체 diff, 로그와 명령 실행 이력. 변경 파일 경로 목록은 이 제외 대상이 아니다.
- 원본 문서의 긴 복사본
- 근거 없는 추정이나 선택하지 않은 대안을 확정된 결정처럼 표현한 내용
- 비밀값, 인증 정보, 개인정보

## 완료 보고

- 작성·갱신·삭제한 `CONTEXT.md` 경로를 알린다.
- 저장한 현재 목표, 현재 상태와 다음 작업을 간결하게 요약한다.
- `문서 반영 필요` 항목을 보고하고, 없으면 `없음`이라고 알린다.
- 파일을 삭제했으면 활성 인수인계와 문서 미반영 사항이 남지 않았다는 근거를 알린다.
